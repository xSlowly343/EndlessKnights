## Window
- 1.1: рамку снимает `WindowController` в `Game.Platform.Windows`: стиль `WS_POPUP | WS_VISIBLE` и `SetWindowPos` с размером полоски. Вызывается из `GameStartup` (Bootstrap) после загрузки сцены, только в сборке: в редакторе окно Unity не трогаем.
- Своё окно ищем через `EnumWindows` по PID и классу `UnityWndClass`, а не через `GetActiveWindow`: при старте окно может быть не активным.
- Под IL2CPP колбэк для WinAPI должен быть статическим методом с `[MonoPInvokeCallback]`, замыкания не маршалятся. Поэтому состояние поиска лежит в статических полях.
- Размер 480×140 пока задан константами в `GameStartup`, их же `ProjectConfigurator` пишет в Player Settings (стартовый размер, без изменения размера). В фазе 11 размер уедет в настройки.
- 1.2: прозрачность через `DwmExtendFrameIntoClientArea` с полями −1 и камеру с фоном (0,0,0,0) и выключенным HDR (`TransparentCamera`). `WS_EX_LAYERED` для этого не нужен.
- Прозрачность работает только на **Direct3D 11** без flip model. На D3D12 (по умолчанию в Unity 6) фон получается чёрным. `ProjectConfigurator` выставляет D3D11 и `useFlipModelSwapchain = false`.
- Оранжевый квадрат `PlaceholderSquare` — временная заглушка для проверки прозрачности, её заменят герой и враг в 6.1.
- Проверка прозрачности без глаз: снять область окна с экрана при запущенной игре и после её закрытия, сравнить пиксели. Фон за окном у Сергея часто меняется (видео, оверлей мониторинга), поэтому надёжнее смотреть на снимок.
- 1.3: `KeepOnTop` ставит `HWND_TOPMOST` через `SetWindowPos` без активации. Проверка: Блокнот, поставленный поверх полоски, оказывается под ней (`WindowFromPoint` в центре полоски даёт окно игры). Если другая topmost-программа перекроет полоску, понадобится повторять вызов по таймеру; пока не нужно.
- 1.5: `ShowInTaskbar` ставит `WS_EX_APPWINDOW` и снимает `WS_EX_TOOLWINDOW`. `APPWINDOW` обязателен: без него окно с `WS_EX_NOACTIVATE` (режим «без фокуса», 1.4) пропадёт с панели задач.
- Иконка игры — временная заглушка `Assets/Game/Art/Icons/AppIcon.png` (оранжевый круг «EK», 256×256), её ставит `ProjectConfigurator`. Заменить на арт из Blender (фаза 12).
- 1.4, режимы фокуса: логика в `FocusMode` (Platform, чистый C#, тесты в `Game.Platform.Tests`). Состояния: Normal → по кнопке NoFocusPending → когда игра потеряла передний план, NoFocus → когда игра снова на переднем плане (Alt+Tab, панель задач), Normal. Промежуточное состояние нужно, потому что клик по кнопке в обычном режиме сам делает игру активной, и без него режим сразу бы выключился.
- При включении режима `WindowController` ставит `WS_EX_NOACTIVATE` и возвращает фокус последнему чужому активному окну (`RememberOtherForeground` каждый кадр, затем `SetForegroundWindow`). Это разрешено, потому что в этот момент игра на переднем плане.
- Кнопка `FocusModeButton` — временный квадрат в правом верхнем углу полоски: серый в обычном режиме, синий в режиме «без фокуса». Клик ловится через Input System; чтобы клики доходили без фокуса, `backgroundBehavior = IgnoreFocus`. Это ввод внутри своего окна, глобальный ввод по-прежнему только через Raw Input (фаза 2).
- Проверка без глаз (скрипт с `SetCursorPos`/`mouse_event` и `SetForegroundWindow` с нажатым Alt): Блокнот активен → клик по игре делает игру активной → клик по кнопке возвращает фокус Блокноту и ставит `NOACTIVATE` → клик по игре фокус не забирает → выбор игры снимает `NOACTIVATE`.
- 1.6: положение и край панели задач берём из `SHAppBarMessage(ABM_GETTASKBARPOS)` (`Taskbar`), прямоугольник полоски считает `StripPlacement` (чистая функция, тесты в `Game.Platform.Tests`). Полоска встаёт вплотную к внутренней стороне панели. По умолчанию — у левого конца (у вертикальной панели — у верхнего), решение Сергея 20.10.2026.
- Перетаскивание: зажать полоску мышью (не на кнопке) и тянуть, полоска едет вдоль панели и не отрывается от неё. Сдвиг вдоль панели (`offset`) ограничен её длиной (`StripPlacement.ClampOffset`). Перетаскивание начинается после сдвига на 4 px (`StripDrag`), поэтому обычный клик остаётся кликом. Курсор берём из `GetCursorPos` в экранных координатах, а не из Input System: окно под курсором само двигается. Работает и в режиме «без фокуса», фокус при этом не уходит.
- Сдвиг пока не сохраняется между запусками; сохраним вместе с настройками (фаза 11) или сейвом (фаза 7).
- Когда появятся клики насквозь (1.8), пустые места полоски перестанут ловить мышь, и тянуть можно будет только за спрайты. Решить в 1.8, нужна ли отдельная ручка.
- `TaskbarDockDriver` раз в секунду перечитывает панель и переставляет окно, если она сдвинулась или поменяла край. Без подписки на `WM_DISPLAYCHANGE`/`WM_DPICHANGED`: это задача 1.7.
- В Windows 11 панель задач нельзя перенести наверх или вбок штатными средствами, поэтому вживую проверен только нижний край (1920×1080, 96 DPI: полоска (1440,892)–(1920,1032), низ полоски = верх панели). Остальные края проверены тестами `StripPlacement`.
- Синтетический клик (`mouse_event` без паузы между нажатием и отпусканием) Input System может не заметить: нажатие и отпускание попадают в один кадр. В скриптах проверки держать кнопку 50–100 мс, как человек.
- 1.7: плеер Unity 6 уже Per-Monitor DPI Aware v2 (проверено `GetWindowDpiAwarenessContext`), поэтому все координаты WinAPI в физических пикселях. Размер полоски 480×140 задан для 96 DPI и масштабируется по DPI монитора с панелью задач (`StripSize.ScaledFor`, `MonitorDpi` через `MonitorFromRect` + `GetDpiForMonitor`): 150% → 720×210, 200% → 960×280. Камера ортографическая с постоянным размером, поэтому картинка растягивается вместе с окном.
- `TaskbarDockDriver` раз в секунду сравнивает край, прямоугольник панели и DPI; смена масштаба в Windows или перенос панели на другой монитор переставляют и пересчитывают полоску. `WM_DPICHANGED` не перехватываем, опрос дешевле подмены оконной процедуры Unity.
- Несколько мониторов: `ABM_GETTASKBARPOS` даёт панель основного монитора, полоска стоит на нём. Выбор монитора — настройка (фаза 11).
- У Сергея один монитор 1920×1080 на 100%, поэтому вживую проверен только этот случай; 150% и 200% — тестами `StripSizeTests` и ручной проверкой Сергея. Менять масштаб Windows агент не может (это системные настройки).
- 1.8, клики насквозь: каждый кадр `ClickThroughDriver` берёт курсор (`GetCursorPos`) и прямоугольник окна, переводит точку в мир камеры и спрашивает `Physics2D.OverlapPoint` (`StripHitTest`). Над спрайтом с коллайдером окно ловит мышь, над пустым местом получает `WS_EX_TRANSPARENT | WS_EX_LAYERED`, и клик уходит окну под полоской. Стиль меняется только при смене состояния.
- `WS_EX_LAYERED` требует `SetLayeredWindowAttributes(alpha 255)`, иначе окно пропадает. С D3D11 и DWM-прозрачностью картинка при этом не меняется (проверено снимком экрана).
- Пока кнопка мыши зажата, состояние не меняется (`ClickThroughPolicy`): можно утащить полоску за спрайт, даже если курсор соскочил на пустое место, а зажатая где-то ещё кнопка не «хватает» окно.
- Всё, что должно ловить мышь, обязано иметь `Collider2D`: заглушка-квадрат и кнопка фокуса его получают. Тянуть полоску теперь можно только за спрайты; отдельная ручка пока не нужна.
- Решение запаздывает на кадр: если курсор прыгнул на спрайт и сразу кликнул в том же кадре, клик может пройти насквозь. Для человека незаметно, в скриптах проверки нужна пауза после `SetCursorPos`.
- 1.9, фуллскрин: `FullscreenDriver` раз в секунду спрашивает `SHQueryUserNotificationState`. Состояния Busy (полноэкранное окно, в том числе видео в браузере), RunningFullscreenDirect3D и PresentationMode прячут окно (`ShowWindow(SW_HIDE)`) и ставят рендер на паузу (`OnDemandRendering.renderFrameInterval = 60`). Update и логика продолжают идти. Обратно — `SW_SHOWNOACTIVATE`, чтобы не отобрать фокус.
- Пока окно спрятано, иконки игры на панели задач тоже нет. Если это будет мешать, можно вместо скрытия делать окно полностью прозрачным.
- Проверка без глаз: открыть из PowerShell форму без рамки во весь экран и поверх всех, сделать её активной: состояние оболочки 5 → 2, полоска пропадает (`IsWindowVisible` = False) и появляется через секунду после закрытия формы.
- 1.10, трей: `TrayIcon` (Platform/Tray) создаёт скрытое окно класса `EndlessKnightsTray` на главном потоке Unity (его сообщения разбирает цикл сообщений Unity), добавляет иконку через `Shell_NotifyIcon`, иконку берёт из своего exe. Правый клик строит меню (`TrayMenu`, чистый C#) и показывает `TrackPopupMenu`; выбор приходит как `WM_COMMAND` и ставится в очередь, `TrayDriver` разбирает её в `Update`. При выходе иконка удаляется.
- Под IL2CPP `Process.MainModule` не работает (падает с `ArgumentNullException`), путь к exe берём через `GetModuleFileName`.
- Пункты меню: «Пауза» (сейчас только `Time.timeScale = 0`; в фазах 2 и 5 сюда же подключим паузу ввода и тика), «Клики насквозь» (выключено — вся полоска ловит мышь), «Поверх всех окон» (`HWND_TOPMOST`/`HWND_NOTOPMOST`), «Выход». Состояние не сохраняется между запусками, по умолчанию «Клики насквозь» и «Поверх всех окон» включены.
- Решение Сергея (20.10.2026): полоска прячется только в полноэкранном режиме. Перекрывать её развёрнутыми окнами — через выключение «Поверх всех окон».
- В PowerShell `$null` в строковый параметр P/Invoke превращается в пустую строку: для `FindWindow` передавать `[NullString]::Value`.
- 1.11 (переделано в 1.12): лимит кадров держит не Unity, а свой `FramePacer` (Platform/Timing) со сном в `LateUpdate` последнего по порядку скрипта (`FramePacingDriver`). `FrameRateLimit` только выключает лимит движка: `vSyncCount = 0`, `targetFrameRate = -1`. По умолчанию 60, в трее пункты «Лимит 30/60/144 FPS» (выбор не сохраняется до фазы 11). Пауза рендера в фуллскрине (`renderFrameInterval = 60`) считается от этого лимита: при 60 FPS спрятанная полоска рисует 1 кадр в секунду.
- Почему не `Application.targetFrameRate`: в оконном режиме Unity добирает время до кадра активным ожиданием, и чем ниже лимит, тем больше CPU. Замер на Ryzen 7 7800X3D (8 ядер): 30 FPS — 11.1% всей машины, 60 — 7.5%, 144 — 1.8%. С `FramePacer` + `Thread.Sleep` при `timeBeginPeriod(1)`: 30 — 0.40%, 60 — 0.59%, 144 — 1.33%. Цель 1.12 (≤ 4%) выполнена с запасом.
- `FramePacer` копит расписание: если кадр опоздал, следующий ждёт меньше; если отстали больше чем на интервал, расписание начинается заново. `vSyncCount` для деления частоты не подходит: у Сергея монитор 240 Гц, а 144 на него не делится.
- 1.12: замер CPU — `Tools/measure-cpu.ps1 [-FrameRate 30|60|144]`: запускает сборку, ждёт 10 с, переключает лимит через трей и считает `TotalProcessorTime` за 30 с. Выводит процент всей машины и одного ядра и память.
- Проверка FPS: у Сергея включён оверлей мониторинга (RTSS), он рисует FPS прямо поверх окна игры. Снимок левого верхнего угла полоски показал 60 → 144 → 30 после команд трея.
- 1.13, один экземпляр: в `BeforeSceneLoad` создаём именованный mutex `Local\EndlessKnights.SingleInstance` (`SingleInstance.TryClaim`, через `CreateMutex`, а не `System.Threading.Mutex`, чтобы не зависеть от IL2CPP). Если он уже есть, второй процесс находит окно трея первого (класс `EndlessKnightsTray`), по его PID — окно игры, показывает и активирует его, затем `Application.Quit()`; `Start` второго экземпляра ничего не настраивает. `Local\` — на сессию пользователя: у другого пользователя Windows своя копия игры.
- Активация первого окна работает, только если у второго процесса есть право на передний план: при двойном клике в Проводнике оно есть. Из фонового скрипта Windows его не даёт, поэтому скрипт проверяет только «второй закрылся, первый живёт».
- Проверка без глаз: PowerShell с `GetWindowLongPtr` и `GetWindowRect` по `MainWindowHandle` запущенного exe. На 1.1 стиль `0x94000000` (без `WS_CAPTION`), окно и клиентская область 480×140.

## Core
- Слои сборок (0.3): Core → Platform.Windows, Presentation, Net → Bootstrap → Editor. Ссылаться можно только на слой ниже, соседей по слою не связываем. Это проверяет `Game.Architecture.Tests` по файлам asmdef и по скомпилированной Core (нет ссылок на `Unity*`). Новую сборку в `Assets/Game` нужно добавить в таблицу слоёв теста, иначе он упадёт.
- Пустые asmdef Unity не компилирует, поэтому сборки без кода появятся в Test Runner и в решении только с первым файлом.
- `Game.Platform.Windows` собирается только для редактора и Windows x64, в нём разрешён `unsafe` под P/Invoke.
- `Game.Core` собирается и тестируется без Unity: `Tools/test-core.ps1` (проекты в `Tools/CoreBuild`). Исходники лежат в `Assets/Game/Core` и `Assets/Tests/Core.Tests`, csproj только подключают их. Это даёт быстрые тесты до установки Unity и пригодится для CI (0.4) и сервера.
- Сборка Core ограничена тем, что умеет Unity 6: `netstandard2.1` и C# 9. Если в Core появится API новее, сборка упадёт раньше, чем в Unity. `Nullable` включён через `csc.rsp` рядом с asmdef.
- Предупреждения в Core считаются ошибками.
- `BigNumber` (3.1–3.2): мантисса по модулю в [1, 10), знак хранится в мантиссе, потому что HP минус урон может уйти в минус. Ноль всегда `0e0`, `default` тоже ноль. Слагаемое меньше в 10^17 раз и более отбрасывается (точность double около 16 знаков). `Pow` разрешён только для неотрицательных чисел; степень считается через логарифм, а целая часть показателя отделяется заранее, чтобы не терять точность на огромных показателях. `Log10` ведёт себя как `Math.Log10`: ноль даёт −∞, отрицательное — NaN. Равенство точное по полям, поэтому в тестах значения после арифметики сравниваются с допуском.

## Tools и MCP
- CI (`.github/workflows/ci.yml`) идёт на self-hosted runner `HOME-PC` на ПК Сергея (`C:ctions-runner`, метки `unity`, `windows`; запуск через `run.cmd`, автозапуск через файл в папке «Автозагрузка»). Сначала тесты Core через dotnet, потом `build.ps1 -Tests`: EditMode-тесты Unity и сборка IL2CPP. Логи Unity прикладываются к прогону как артефакт `unity-logs`. Пока ПК выключен, прогоны ждут в очереди.
- `actions/checkout` с `lfs: true` на нашем runner оставлял вместо PNG LFS-указатель, и Unity не находил иконку. Поэтому в CI отдельный шаг `git lfs pull`.
- `checkout` с `clean: false`, чтобы не стирать `Library` между прогонами, иначе каждый прогон заново импортирует проект.
- Проект на **Unity 6000.6.6f1** вместо 6.3 LTS из engine-spec: Сергей поставил 6.6, решили остаться на ней (19.10.2026). Переход на следующую LTS с 6.6 простой, откат на 6.3 не нужен.
- Проект создан из встроенного шаблона `2d-cross-platform` (URP 2D Renderer, `Assets/Settings`). Лишние пакеты шаблона убраны из `manifest.json`: tilemap, spriteshape, aseprite, psdimporter, animation, timeline, visual scripting, Rider, collab, обучающий фреймворк. 2D Animation вернём, только если понадобятся кости (engine-spec §1).
- Input System остался из шаблона: он нужен для ввода в редакторе (2.13), а в сборке ввод идёт через Raw Input.
- Настройки игрока задаёт код, а не ручная правка: `Game/Apply Project Settings` (`ProjectConfigurator`) — IL2CPP, .NET Standard, Windows x64, работа в фоне, оконный режим, имя продукта «Endless Knights», компания `EndlessKnights` (по имени репозитория). Сборка: `Game/Build Windows` или батч-режим `-executeMethod Game.Editor.WindowsBuild.Build`, exe в `Builds/Windows`.
- Для IL2CPP нужен Visual Studio с набором «Разработка классических приложений на C++» и Windows SDK; без него сборка падает с `ToolchainNotFoundException`. Первая сборка IL2CPP идёт около 3 минут.
- `build.ps1` в корне (0.5): `powershell -ExecutionPolicy Bypass -File build.ps1` собирает exe, с `-Tests` сначала гоняет EditMode-тесты. Unity ищется по версии из `ProjectVersion.txt` в папке Unity Hub, другой путь задаётся `-UnityPath` или переменной `UNITY_EDITOR`. Логи и результаты тестов в `Builds/Logs`. Пока открыт редактор с этим проектом, батч-режим Unity не запустится.
