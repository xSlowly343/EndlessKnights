# Базовые модели героя на Spine: этап 1, исследование

Отчёт агента от 09.11.2026 по заданию «Rift Warden: универсальная система 2D-персонажей и скелетной анимации». Это этап 1: исследование и выбор архитектуры. Код игры и игровые данные не менялись. Решения, без которых нельзя начинать этап 2 (графику), собраны в §9.

## 1. Коротко

- **Проект — Unity 6.6, C#.** Герой в полоске сейчас синий квадрат-заглушка. Spine и пакет 2D Animation в проекте не установлены. Своя пиксельная кукла v8 (`hero-look.md` §13–18) существует только как скрипты Python, которые запекают покадровые листы. В игру она не подключена.
- **spine2D-mcp редактором Spine не управляет.** Это генератор JSON из PSD с заглушками вместо предпросмотра. Под требования задания (100+ костей, меши, веса, скины, физика) он не подходит, ставить его не советую (§3).
- **Замена MCP проверена.** Агент пишет скелет Spine 4.3 в JSON сам и проверяет его в официальном рантайме `spine-webgl` 4.3.13 в Chromium без редактора: меш с весами на двух костях, IK с коленом и физика волос работают (§4).
- **Spine подходит к проекту.** Рантайм `spine-unity` 4.3 работает с Unity 6. Есть три условия: версия редактора и рантайма совпадают до минорной цифры; меши, веса, IK и физика есть только в Spine **Professional**; у кого-то в команде должна быть лицензия Spine (§5).
- **Главный конфликт — масштаб и стиль.** Герой в полоске ростом около 48 px (×2 на экране). При таком росте палец занимает 1 px, а деформация меша ломает пиксельную сетку. Предлагаю такой путь: рисуем и ригаем в 4× (≈ 200 px), а в игре выводим пикселями через рендер в низкое разрешение (§6). Это нужно утвердить вместе со стилем: референс dark fantasy или стиль Cainos из `hero-look.md` §18.

## 3. spine2D-mcp: что в нём на самом деле

Изучены README, `SPINE2D_INTEGRATION.md` и весь исходный код (1 492 строки; один коммит «fix: resolve Spine import errors»).

**Инструменты MCP (5 штук):** `import_psd`, `setup_character`, `generate_animation`, `preview_animation`, `export_animation`, плюс ресурс `spine2d://characters`.

**Как он работает:**
- С редактором Spine не связан. Он пишет файл JSON, который человек сам импортирует в Spine через «Import Data».
- Риг строится по ключевым словам в именах слоёв PSD (`hair`, `arm_left`, `foot_right`…). Получается не больше 17 костей: root, body, head, руки, кисти, ноги, стопы, волосы, глаза. Кость ставится в центр первого подходящего слоя.
- Мешей, весов, путей, физики и transform-ограничений нет. IK строится простой. Скин один, `default`.
- Анимации — около десяти готовых шаблонов (wave, jump и подобные) с подбором по словам в описании. Вызов OpenAI в коде закомментирован.
- `preview_animation` и экспорт в `png`/`gif` пишут в файл текст `"GIF output placeholder"`, а не картинку.
- Формат файла — Spine 4.1. Зависимости старые: `pillow==9.0.0`, `flask==2.0.1`, `openai==0.27.0`.

**В этом окружении** MCP не подключён: в `.mcp.json` проекта только UnityMCP, и тот сейчас недоступен (ECONNREFUSED). Spine Editor в облаке не установлен, поэтому его версию проверить нельзя.

**Вывод.** Требованиям задания MCP не отвечает: развитый скелет, меши, веса, скины по категориям и физика в нём не поддержаны, а предпросмотр не работает. Ставить его не советую. Если Сергей всё же захочет, установка такая: клонировать репозиторий, `pip install -r requirements.txt`, добавить в настройки Claude Code сервер `python src/main.py --storage ./storage`. Конфигурацию системы агент без согласия не менял.

## 4. Чем заменить MCP (проверено)

Формат JSON Spine открыт и описан, а официальный рантайм читает его без редактора. Конвейер такой:

1. **Агент пишет данные скелета скриптом:** кости, слоты, ограничения (IK, transform, physics), меши с весами, скины, анимации.
2. **Агент проверяет данные в официальном рантайме** `@esotericsoftware/spine-webgl` 4.3.13 в Chromium (Playwright уже стоит в облаке). Позы рендерятся в PNG: можно смотреть стыки, пустоты и растяжения на крайних углах. Это те же диагностические позы, что требуются в §14 задания.
3. **Spine Editor на ПК Сергея:** импорт JSON («Import Data»), ручная правка весов там, где скрипт ошибся, упаковка атласа и экспорт `.skel`. Всё это можно гонять скриптом через командную строку Spine (`Spine -i … -o … -e …`).

**Проба** (`art/heroes/spine/probe/`, результат `probe-result.png`): нога из двух костей, меш на 18 вершин с весами (бедро → голень с плавным переходом у колена), двухкостный IK со стопой-целью и `bendPositive: false`, кость волос с physics-ограничением, анимация «удар ногой» со сдвигом корня. Сначала проверено на 4.3.13, после решения Сергея — на 4.2.120: колено гнётся, меш идёт за костями без разрывов, волосы отстают при рывке до 23° и возвращаются с перехлёстом.

Подводные камни формата, найденные пробой:
- **4.2:** у каждого ограничения (IK, transform, path, physics) должно быть своё поле `order`, разное у всех. Редактор пишет его всегда. Без него рантайм ставит в очередь только первое ограничение с `order: 0`, а остальные молча не работают — так сначала «не работала» физика волос. Генератор скелета обязан нумеровать `order`.
- **4.2:** ограничения лежат в разделах `ik`, `transform`, `path`, `physics`; `drawSkeleton(skeleton, premultipliedAlpha)`.
- **4.3** (на будущее): ограничения в общем массиве `constraints` с полем `type`, флага premultiplied alpha у `drawSkeleton` нет.

Генератор MCP (формат 4.1) ни того, ни другого не учитывает.

Запуск пробы: `npm i`, затем `python3 make_probe.py`, `python3 -m http.server 8765` и `node shot.js`.

## 5. Spine в Unity: совместимость и интеграция

**Рантайм.** `spine-unity` 4.3 ставится в Unity 6 пакетом UPM по git-ссылке из репозитория `EsotericSoftware/spine-runtimes`, ветка 4.3. Правило Spine: major.minor редактора и рантайма должны совпадать. Экспорт из Spine 4.3.x — рантайм 4.3. Агент проверит это, когда Сергей назовёт версию своего редактора.

**Лицензия.**
- Рантайм бесплатен для команды, у которой есть лицензия Spine Editor (Spine Runtimes License).
- Essential (69 $) даёт только кости, слоты, обычные картинки, скины и события. Меши, веса, свободная деформация, IK, transform, path и physics-ограничения, клиппинг — только в **Professional (379 $)**.
- Почти всё в задании (§5, §6, §10) требует Professional.
- Раньше Сергей просил «бесплатный вариант» (`hero-look.md` §11). Покупку должен подтвердить он.

**Формат экспорта.**
- В игру идёт бинарный `.skel` (меньше и быстрее грузится), атлас `.atlas` и PNG.
- Исходник `.spine` и JSON-экспорт хранятся в репозитории (LFS) рядом с исходными картинками частей.
- Фильтр атласа: Nearest (пиксели). Premultiplied alpha — как в шейдере `Spine/Skeleton` с URP 2D.

**Загрузка.** Файлы лежат в `Assets/Game/Art/Characters/…`. `SkeletonDataAsset` создаётся импортёром spine-unity. Герой — компонент `SkeletonAnimation`: он сам считает кадр и не тянет Animator, поэтому дешевле. Заглушка в `BattleView` меняется на `HeroView` в `Game.Presentation`. `Game.Core` про Spine не знает.

**Синхронизация с логикой (10 Гц).**
- Ядро выдаёт события: удар, скилл, урон по герою, переход к врагу.
- `HeroView` переводит их в треки `AnimationState`:
  - трек 0 — стойка, ходьба, связка ударов;
  - трек 1 — верх тела поверх ног (каст, блок);
  - трек 2 — лицо (моргание, эмоции);
  - трек 3 — добавочное дыхание.
- Сопоставление «событие → имя анимации и скорость» лежит в JSON (`hero-anims.json`), а не в коде.
- Ссылки на `Animation` кэшируются при загрузке, поэтому в кадре нет поиска по строке и нет аллокаций.

**Экипировка.**
- Каждый предмет — свой скин Spine с именем по категории: `body/male`, `hair/ponytail_01`, `armor/chest/plate_03`, `weapon/sword_1h_01`.
- При смене снаряжения код собирает общий скин через `Skin.AddSkin`, а не в каждом кадре.
- Для меньшего числа draw call скин перепаковывается в один атлас: `GetRepackedSkin` в spine-unity.
- Редкость — смена цвета слота (tint и dark color) или своего вложения.

**Вторичная анимация.**
- Physics-ограничения Spine 4.2+ на волосах, плаще, полах, ремнях.
- `skeleton.physicsTranslate` передаёт рывок героя.
- Для фигур друзей и при скрытом окне: `Physics.pose` или реже обновлять скелет. В spine-unity обновление невидимых скелетов отключается (`UpdateTiming`, `updateWhenInvisible`), это держит бюджет 1% CPU.

**Общие анимации для мужской и женской моделей.** Анимации в Spine хранят повороты относительно позы покоя, а смещения прибавляются к ней. Поэтому, если у двух скелетов одинаковые имена и иерархия костей, один и тот же ключ даёт одинаковое движение даже при разных длинах костей. План:
- два скелета `hero_male` и `hero_female` с одним списком костей, но своими длинами и положениями (пропорции);
- библиотека анимаций пишется один раз;
- скрипт агента копирует её между скелетами по именам костей;
- анатомически разные анимации (стойка, ходьба, дыхание) переопределяются отдельно;
- будущие пропорции (крупный, худой, низкий) — новый «профиль тела» на тех же костях.

## 6. Масштаб и стиль: что нужно решить

Требования задания рассчитаны на крупного HD-героя: пальцы из трёх сегментов, веки, брови, деформация живота. Игра — пиксельная полоска:
- герой ≈ 48 px ростом, на экране ×2;
- кисть — 3–4 px, глаз — 2×3 px (`hero-look.md` §15).

При таком росте:
- три сегмента пальца — меньше пикселя каждый;
- поворот и деформация пиксельной картинки в рантайме дают «ломаные» и полупрозрачные пиксели. Именно поэтому кукла v8 поворачивает части через RotSprite и запекает кадры.

Варианты:

| Вариант | Как | Плюсы | Минусы |
| --- | --- | --- | --- |
| **А. HD-риг, пиксельный вывод** (рекомендую) | Части рисуются в 4× (рост ≈ 200 px), риг и меши полные. В игре герой рендерится в текстуру 1× (Pixel Perfect Camera URP 2D или своя RT с Nearest) и выводится ×2 | Пиксельная сетка общая с врагами, деформации чистые. Тот же риг крупно в окне героя (14е.7) и на экране выбора (14в.9): там видны пальцы и мимика | Мелкие детали (пальцы, веки) в полоске почти не видны; нужен шаг рендера в RT |
| Б. Пиксельный риг 1× | Части в размере полоски, меши минимальные, повороты на Nearest | Дешевле всего рисовать | Ломаные пиксели при поворотах, пальцы и мимика не читаются, для Spine Professional почти нет работы |
| В. HD-герой без пикселей | Рисованный герой ≈ 200–300 px, сглаживание | Вся мимика и деформация видны | Расходится со всеми пиксельными врагами и фонами |

Пальцы при варианте А:
- в скелете у каждого пальца три сегмента (крупный показ, хват оружия);
- в полоске кисть берётся из набора поз-вложений: кулак, хват, ладонь, указание, щепоть;
- аниматору не нужно крутить 15 костей ради кадра в 4 px.

**Стиль.** Приложенный референс («Dark Fantasy Heroes Vol. 1») — тёмное фэнтези: фигура около 60 px, чёрная обводка, насыщенные фиолетовый, красный и сталь, бо́льшая детализация брони. А Сергей 09.11.2026 утвердил свою куклу «точь-в-точь как у Cainos»: тёплая коричневая обводка, приглушённая палитра, 48–53 px (`hero-look.md` §18). Это два разных стиля. Нужен один, иначе риг придётся перерисовывать. Сам набор с референса покупной, агент берёт из него только приёмы, без пикселей.

## 7. Предлагаемая архитектура (после ответов из §9)

**Кости** (имена `snake_case`, сторона суффиксом `_l` / `_r`, контроллеры с приставкой `ctrl_`, крепления с `anchor_`):
- корпус: `root`, `ctrl_cog` (центр тяжести), `hips`, `pelvis`, `spine_lower`, `spine_mid`, `spine_upper`, `chest`, `ribcage`, `belly` (деформация живота), `breast_l/r` у женского скелета и `pec_l/r` у мужского (одно назначение, разные веса), `scapula_l/r`, `neck`, `head`, `jaw`;
- лицо: `eye_l/r`, `pupil_l/r` (взгляд), `lid_up_l/r`, `lid_low_l/r`, `brow_l/r` (две кости на бровь: внутренняя и внешняя часть), `nose`, `mouth`, `mouth_corner_l/r`, `lip_up`, `lip_low`, `hair_root`;
- рука (на сторону): `clavicle`, `shoulder`, `arm_upper`, `elbow` (корректор локтя), `forearm`, `forearm_twist` (вращение запястья без скручивания меша), `wrist`, `hand`, `palm`, пальцы `thumb_1…3`, `index_1…3`, `middle_1…3`, `ring_1…3`, `pinky_1…3`, крепления `anchor_hand`, `grip_hand`;
- нога (на сторону): `hip`, `leg_upper`, `knee` (корректор колена), `leg_lower`, `ankle`, `heel`, `foot`, `toe`;
- контроллеры: `ctrl_hand_ik`, `ctrl_elbow_pole`, `ctrl_foot_ik`, `ctrl_knee_pole`, `ctrl_head_look`, `ctrl_chest`, `ctrl_pelvis`;
- крепления: `anchor_back`, `anchor_hip_weapon_l/r`, `anchor_ear_l/r`, `anchor_neck`, `anchor_belt`, `anchor_backpack`, `anchor_wings`, `anchor_fx_hand_l/r`, `anchor_fx_head`;
- вторичное (цепочки с physics): `hair_front_1…3`, `hair_side_l/r_1…3`, `hair_back_1…4`, `cape_l/m/r_1…4`, `skirt_f/b/l/r_1…3`, `sleeve_l/r`, `belt_tail_1…3`.

Итого ≈ 150 костей. Цепочки волос, плаща и юбки — «скиновые» кости (`skin: true`): они включаются только со скином, которому нужны. С одним базовым телом активно около 95 костей.

**IK/FK.** IK рук и ног со смешиванием `mix` 0…1: ключ на `mix` и есть переключатель IK/FK в Spine. Полюс локтя и колена — через направление сгиба плюс transform-ограничение от кости `pole`. Хват двуручного оружия — IK второй руки на `grip_hand`.

**Слоты и порядок отрисовки** (сзади вперёд): дальние волосы и плащ → дальняя рука с оружием и щитом → дальняя нога → таз, корпус, грудь, броня корпуса → ближняя нога → голова, лицо, волосы спереди → ближняя рука → оружие в ближней руке → передние аксессуары и эффекты. Смена сторон — ключами порядка отрисовки в анимациях поворота. Каждый слот брони стоит над своей частью тела, поэтому предметы разных категорий не спорят за один слот.

**Скины:** `body/male`, `body/female`, `face/<вариант>`, `hair/<имя>`, `cloth/<слот>/<имя>`, `armor/<head|chest|hands|feet>/<материал>_<номер>`, `weapon/<тип>/<имя>`, `acc/<точка>/<имя>`. Правило: скин меняет только свои слоты, а связь «предмет → слоты» лежит в JSON.

**Лицо.**
- Глаза, веки и брови двигаются костями и мешами.
- Формы рта (покой, A, E, O, U, M, улыбка, оскал) и варианты глаз (открыт, полуприкрыт, закрыт, прищур) — сменные вложения в слотах `mouth` и `eye_l/r`. Новая эмоция — новый набор вложений и ключей на тех же костях.

**Структура в репозитории.** Без параллельного дерева «RiftWarden/…» из задания:

## 11. Этап 2: графика базовых моделей (09.11.2026, на утверждение)

**Как сделано.** Все части рисует скрипт по параметрам тела, а не руками по пикселям, поэтому пропорции меняются правкой цифр:

Запуск: `pip install cairosvg`, затем `python3 render_parts.py` и `python3 render_parts.py sheets` в `art/heroes/spine/tools/`.

**Что получилось.** Для каждой модели в `base/<male|female>/artwork/`:

- `parts.json` — для каждой части слот, слой, оттенок, рамка в мировых единицах и точки суставов. Эти точки станут костями на этапе 3.

**Решения по рисунку.**
- **Без швов на суставах.** Бедро с голенью, плечо с предплечьем и таз с грудью — одна картинка. На этапе 3 это меш с весами на две-три кости, поэтому колено, локоть и талия гнутся без стыка. Это и было замечание Сергея к кукле v2: «видно, что голень отдельно».
- **Обводка по силуэту части.** Тёплая тёмно-коричневая (70, 38, 30) — чуть темнее, чем у Cainos (92, 48, 28), иначе тёмная броня из референса с ней сливается. Внутренние линии — тень своего цвета.
- **Чистый пиксель на выходе.** Цвета каждой части сведены к её палитре, прозрачность — только «да или нет». Поэтому при выводе в 1× с выборкой Nearest получается чистый пиксель-арт без полупрозрачной каши. Проверка — `base/preview/lineup_1x_x4.png`.
- **Свет спереди сверху справа:** тень по левому и нижнему краю, блик по правому и верхнему.
- **Дальняя рука и нога** (левые, справа на экране) — те же картинки с оттенком 0,82 в слоте Spine, отдельная перерисовка не нужна.
- **Стиль — смесь.** Пропорции Cainos: рост 52 / 51 px, голова около трети роста, руки висят до бёдер. Палитра ближе к референсу: тёмные волосы с фиолетовым и серебро, багровая и фиолетовая туника, сталь и кожа. Отдельно от этого не всё готово: доспехи как в референсе нарисует этап 4 (скины брони).

### 11.2. Обводка без «лего» и причёски девушки (09.11.2026)

Сергей: «Каждый элемент будто со своей обводкой, создаётся впечатление, что он будто из лего… и у девушки причёска будто не так должна быть».

**Обводка.**
- Раньше каждая часть обводилась общим тёмным цветом, поэтому рука, нога, волосы и туника читались отдельными кубиками.
- Теперь край каждой части — самый тёмный тон её собственного материала (`svgkit.Part` с `outline_color=None`). Рука на фоне тела отделена тёмной кожей, волосы на лице — тёмным тоном волос. Так у Cainos: линия есть, но в цвет вещи.
- Тёмная обводка (96, 54, 38) идёт только по силуэту всей собранной фигуры: в превью это `render_parts.silhouette`.
- В игре то же делает проход обводки по текстуре героя 1× (вариант А). Обводка всегда по внешнему краю при любом сочетании одежды и в любой позе, поэтому её не нужно рисовать в каждой части.

**Причёски девушки.** Раньше волосы висели одинаково по обе стороны головы, как колокол. При повороте головы вправо масса волос должна уходить назад, влево на экране, а со стороны лица остаётся только короткая прядь у щеки. Сделаны три причёски — это отдельные скины волос, из них Сергей выбирает основную:
- `long` — длинные волосы, уходят за спину до пояса (цепочка костей `hair_back_1…3`), прядь перед ухом;
- `bob` — каре до плеч, как у героини в шапке Санты;
- `ponytail` — хвост с золотой резинкой, висит за спиной (цепочка `hair_tail_1…3` под физику), короткая прядь у щеки.

Части волос теперь называются `hair_<причёска>_<часть>` (`hair_short_front`, `hair_long_back`, `hair_ponytail_tail`), а слоты — `hair_back`, `hair_front`, `hair_side_l`, `hair_tail`, `hair_tie`. Старые файлы `hair_back`, `hair_front`, `hair_side_l`, `hair_side_r` в `artwork/png` и `artwork/svg` больше не используются; удалить их — после согласия Сергея.

### 12.1. Как устроена кукла v8

- **Части.** Нарисованы вручную пиксель-артом 1× и записаны текстом, по букве на пиксель (`art/heroes/doll/src/front.py`, `body.py`); буква — материал и тон из `pal.py`.

### 12.4. Диагностические позы (09.11.2026)

`tools/doll_diag.py` ставит позы прямо на кости рига в официальном рантайме 4.2. Наборов четыре: мужская база, женская база, мужчина с топором, мужчина с посохом. Итоги лежат в `base/hero/diagnostics/`:
- `poses_<набор>.png` — все позы;
- `zoom_<набор>.png` — каждая поза крупно (×4);
- `defects.json` — автоматическая проверка.

**31 поза** по списку §14 задания: поворот головы вверх и вниз, наклон корпуса вперёд и назад, скручивание (виды торса «профиль» и «спина» со сдвигом плеч), рука вперёд, вверх, над головой и назад, локоть 90° и 150°, переразгиб, запястье ±70°, дальняя рука вверх и согнутая, присед и глубокий присед, прыжок с поджатыми ногами, недостижимая цель IK, удар ногой вперёд, высокий и назад, широкая стойка, выпад, наклон стоп, разворот корпуса при неподвижных ногах, сложная комбинированная поза, ноги в FK (IK выключен).

**Автопроверка.** Каждая конечность (дальняя и ближняя нога, дальняя рука, ближняя рука с оружием, торс с головой) рендерится отдельно. Если её силуэт распадается на куски, в суставе дыра.

**Найдено и исправлено:**
- **Колено при сильном сгибе.** Бедро и голень v8 — жёсткие прямоугольники с осью в колене, поэтому при глубоком приседе, ударе ногой и в FK на внешнем углу колена открывался зазор, и нога читалась комком. Добавлена наколенная заплатка `knee_cap` в цвете штанов (4×4, на кости голени, между бедром и голенью) — тот же приём, что v8 делает на локте. После правки разрывов нет ни в одной позе; сверка с v8 почти не изменилась (1,4–7,2%).

**Проверено, правка не нужна:**
- плечо, локоть, запястье на всех углах;
- голова на шее при ±25°;
- стык торса с тазом при наклоне −35°: угол торса уходит на таз, дыры нет;
- стопы держат горизонт и наклоняются;
- при недостижимой цели IK ноги выпрямляются и отрываются от земли — правильное поведение;
- дальняя рука, поднятая за головой, видна только кусочком у плеча — естественно для руки за телом.

**Замечание, не дефект рига.** Посох в базовой стойке держится как меч (остриём вниз и назад). У v8 для посоха своя стойка (`sw = −18`, посох стоит). Её надо перенести отдельной анимацией `Idle_staff` вместе с кастом (§12.3).

**Как броня садится на риг** (`tools/armor.py`, части — текстовый пиксель-арт в стиле v8, свет справа):
- **Доспех** заменяет у наряда торс во всех трёх видах (к зрителю, профиль, спина), плечо (обычное и короткое), предплечье с рукавом, налокотник и полу. Поэтому вид торса в анимациях меняется сам, и цвет наряда нигде не просвечивает.
- **Перчатки** заменяют кисть; наруч лежит в новом слоте `bracer_<сторона>` над предплечьем.
- **Сапоги** заменяют голень и стопу (у v8 голень и есть сапог).
- **Шлем** — новый слот `helmet` над волосами, на кости головы. Капюшоны обрамляют лицо, колпак выше головы.
- **Сборка без конфликтов.** Скины добавляются по порядку: тело, волосы, глаза, наряд, оружие, затем `helmet/…`, `chest/…`, `gloves/…`, `boots/…`. `Skin.addSkin` заменяет вложение с тем же именем в том же слоте, поэтому вещь подменяет часть наряда, а пустой слот оставляет наряд.
- **Имена скинов:** `<слот>/<материал>_r<редкость>`, например `chest/plate_r6`. Можно носить разные материалы и редкости на разных слотах.

**Редкость — палитра** (`armor.palette`):
- Отделка (обод, пряжки, кант) и камень — в цвете редкости из `items.md` §3.
- У лат и кожи сам металл и кожа подкрашиваются цветом редкости: до Необычной чистые, Редкая и Эпическая слегка, с Легендарной заметно.
- Ткань окрашена целиком (тёмный тон цвета редкости), отделка у неё золотая.
- Свои палитры у трёх высших: Разломная — радуга по тонам, Астральная — тёмно-синяя со звёздными бликами, Первозданная — белое пламя с золотом.
- Свечение и анимация рамок (`visual-style.md`) — эффект движка, в текстурах их нет.

**Проверка** (`tools/doll_armor_preview.py`), картинки в `base/hero/preview/`:
- `armor_sets.png` — мужчина и женщина без брони, в латах, коже и ткани r4, в смешанном наборе r5 и только в шлеме;
- `armor_rarities.png` — латы, кожа и ткань во всех 11 редкостях;
- `armor_poses.png` — каждый материал в 10 крайних позах, вместе с автопроверкой разрывов (`armor_defects.json`: разрывов нет);

После добавления слотов сверка с v8 и диагностика базы не изменились.

**Найдено и исправлено по ходу:**

### 13.1. Броня v2: шесть разных образов (10.11.2026)

Сергей: «А можно делать броню более красивой, проработанной? А то всё выглядит одинаково» — и прислал примеры: Dark Fantasy Heroes и героев Cainos.

**Почему было одинаково.** Все комплекты были одним шаблоном с разной окраской: одинаковый силуэт, кольца и полоски. Богатство в примерах держится на четырёх вещах:
1. **Силуэт:** закрытый шлем, наплечники, плащ и щит у Iron Knight; глубокий капюшон с тенью у Arcane Mage; капюшон с маской-шарфом у Ash Rogue; плюмаж у рыцаря Cainos; меховая опушка у героини в костюме Санты.
2. **Слои материалов:** латы поверх ткани, табард поверх брони, кожаные ремни, мех.
3. **Детали и знаки:** заклёпки, крест на табарде, пряжки, сумки, вышивка.
4. **Движение:** плащи и хвосты шарфа.

**Что сделано.** Каждая база из `items.md` §7.4 (ранняя и поздняя для каждого материала) стала отдельным образом:

| База | Шлем | Доспех и остальное |
| --- | --- | --- |
| `plate_early` | кольчужный капюшон с кольцами шахматкой, налобный обод с камнем, кольчужная бармица до плеч | кольчуга с кожаным поясом и подолом, кольчужные рукава |
| `plate_late` | шлем ярла: рога, наносник, нащёчник, бармица | латы стража: кираса, большие наплечники, **табард с эмблемой-крестом** в цвете редкости, **плащ**; большие рукавицы и сабатоны с наколенником |
| `leather_early` | кожаный капюшон со складками | куртка с ремнём наискосок, **меховая опушка** на подоле, манжетах и голенищах |
| `leather_late` | капюшон с тенью под краем и **маской-шарфом** | доспех ветров: перекрещённые ремни, пояс с двумя пряжками и **сумками**, ткань в цвете редкости, **хвост шарфа** за спиной |
| `cloth_early` | колпак со звёздочками | мантия с вышивкой, поясом и кистью, широкие рукава |
| `cloth_late` | капюшон с **венцом и камнем**, тень над глазами | облачение провидца: **накидка-пелерина**, звёзды по мантии, пояс с камнем, **длинный плащ** со звёздами; открытые сандалии |

**Изменения в риге:**
- новый слот `cape` в самом начале заднего слоя, кость `cape` от плеч с physics-ограничением (`cape_physics`);
- плащ строится функцией `armor.make_cape` (ширина вверху и внизу, длина, звёзды), поэтому плащи легко делать новые;
- рейка палитры расширена: ткань в цвете редкости (`D T t g` — табард, плащ, шарф, пелерина), мех (`J K k j`), тень капюшона (`z`), блик металла (`W`);
- скины теперь `<слот>/<база>_r<редкость>`, например `chest/plate_late_r6`. Всего 6 баз × 4 слота × 11 редкостей: 1034 вложения, 290 скинов.

**Найдено и исправлено по ходу:**
- плащ шириной с таз целиком прятался за тазом и бёдрами — плащ стал до щиколоток, расширяется книзу и висит с наклоном назад;
- хвост шарфа был нарисован вперёд и короче торса — развёрнут назад и удлинён;
- меховой воротник не виден: голова (16 px) спереди целиком закрывает верх торса (11 px) — мех перенесён на подол, манжеты и голенища. Это общее правило для брони: **детали на верхних 4 рядах торса спереди не видны**, их место — плечи-наплечники, пояс, подол и плащ.

**Проверка:**
- разрывов нет в 10 крайних позах для всех шести баз (`armor_poses.png`);
- сверка с v8 и диагностика основы не изменились;
- превью: `armor_sets.png` (шесть образов r4 и смешанный набор r6 на обоих героях), `armor_rarities.png` (поздние базы во всех 11 редкостях), `armor_play_*.gif` (связка в латах стража r6, облачении провидца r5, доспехе ветров r7).

### 13.2. Массивная броня и аксессуары по редкости (10.11.2026)

**Поиск в интернете (10.11.2026), коротко:**
- Европейский латный доспех: горжет; наплечник (pauldron) с усилителем (gardbrace) и диском (besagew); налокотник (couter); наруч; юбка из полос на поясе (faulds) и набедренные пластины (tassets); пластины поясницы (culet); набедренник, наколенник (poleyn), поножи, сабатоны.
- Стили: «готический» — угловатый и шипастый; «максимилиановский» — рифлёный.
- Японский о-ёрой: лакированные пластинки на шнурах, квадратные наплечники, шлем с рогами-гребнем, маска, флажок-сасимоно за спиной.
- На броне носили табарды с гербами (с них пошла геральдика), гребни и плюмажи, флажки, пояса с сумками, меха, цепи.
- В фэнтези: гипертрофированные многоярусные наплечники («фирменный стиль» жанра), глыбоподобные тяжёлые комплекты (Havel в Dark Souls), шипы и черепа у «тёмных рыцарей», крылья и нимб у «божественной» брони; необычные материалы — кость, кристалл, чешуя, кора.
- Для маленьких спрайтов: сначала крупный силуэт, детали последними; наплечники — самое трудное место, им нужны крупные простые формы; мелкие детали не накладывать друг на друга.

**Решения Сергея 10.11.2026:**
1. Броня заметно массивнее (силуэт ≈ 1,3 тела), и тяжесть растёт по базе: ранние вещи легче, поздние тяжелее.
2. Нужны все виды аксессуаров: геральдика и ткань, походные, трофеи, магия и святость.
3. С редкостью аксессуаров больше.
4. Нужны все стили: японский, готический, необычные материалы, божественный.
5. Щит — отдельный предмет второй руки.
6. Оружие у персонажей будет разное — риг и броня не должны ему мешать.

**Сделано — массивность:**
- поздние латы: наплечники 9 px с двумя ярусами и кантом, рукавицы 5 px, сабатоны 8 px, наколенники с «крылом», юбка из полос и набедренные пластины (торс 13 px);
- поздняя кожа: многослойный наплечник 6 px, перчатки 4 px, сапоги 5 px;
- поздняя ткань: пелерина на плечах 6 px;
- ранние базы: умеренные наплечники 5 px (кольчужный, меховой).

**Сделано — аксессуары** (`tools/armor_acc.py`):
- Новые слоты и кости:
  - `crest` над шлемом;
  - `pauldron_deco_*` на наплечниках;
  - `belt_front` на поясе;
  - `belt_hang` на поясе, с физикой;
  - `back_item` за спиной, с физикой, отодвинут назад за край головы;
  - `offhand` во второй руке, держит горизонт.
- Аксессуар принадлежит вещи: гребень — шлему, остальное — доспеху.
- Ступени по редкости (`TIER`, каждая ступень добавляет к прошлым, новая вещь в том же месте заменяет старую):

| Редкость | Ступень | Что появляется |
| --- | --- | --- |
| 1–3 (Простая — Необычная) | 0 | голая броня |
| 4–5 (Редкая, Эпическая) | 1 | вещи на поясе: сумка, футляр со свитком, ленты |
| 6–7 (Легендарная, Мифическая) | 2 | плюмаж или украшения на плечах (печать с лентами, руны); подвес: фонарь, фляга, кристалл |
| 8–9 (Древняя, Разломная) | 3 | знамя за спиной; трофеи: шипы, цепь с черепом, мех, рога, череп на плече |
| 10–11 (Астральная, Первозданная) | 4 | крылья (светлые или тёмные) или нимб |

- Темы по базам (`THEMES`):
  - ранние латы — сумка, печать, шипы и цепь с черепом, нимб;
  - поздние латы — ленты, плюмаж и печать, знамя с гербом, крылья и нимб;
  - ранняя кожа — сумка, фонарь, мех и рога, руны;
  - поздняя кожа — сумка, фляга, череп и цепь, тёмные крылья;
  - ранняя ткань — свиток, фонарь, руны, нимб;
  - поздняя ткань — свиток, руны и кристалл, нимб, крылья.
- **Щиты** `offhand/<heater|round>_r<редкость>`: геральдический с гербом в цвете редкости и круглый деревянный с умбоном. Слот второй руки стоит перед телом, но за рукой с оружием. Тот же слот пойдёт под парное оружие.

**Найдено и исправлено:**
- знамя и крылья целиком прятались за головой (голова 16 px): крепление за спиной отодвинуто назад, флаг развёрнут назад, крылья и древко сделаны выше головы;
- рамка превью была 64 px и резала знамя — теперь 80 px.

**Проверка:**
- разрывов нет в крайних позах для всех баз;
- сверка с v8 и диагностика основы не изменились;
- превью: `armor_sets.png`, `armor_rarities.png` (лестница редкостей всех шести баз: видно, как растут аксессуары), `armor_poses.png`.

**Оружие разное — что это значит для рига:**

- Задача на 18 видов оружия из `weapons.json` — в следующих шагах.

**Дальше:** стили брони — японский, готический, кость, кристалл, кора, чешуя, божественное золото — отдельными образами с теми же слотами и аксессуарами. Сопоставить стили с сетами, уникальными вещами и косметикой — вопрос к Сергею.

### 13.3. Как сделана броня в TT2 и похожих играх (поиск 10.11.2026)

- **Tap Titans 2.** Пять слотов снаряжения: меч, шлем, нагрудник, аура, слэш ([Giant Bomb](https://Www.Giantbomb.com/tap-titans-2/3030-57373/), вики сообщества [r/TapTitans2](https://libreddit.winscloud.net/r/TapTitans2/wiki/equipment)).
  - Видны на герое шлем, нагрудник и меч; аура и слэш — эффекты.
  - Вещи падают с боссов. У каждой редкости, кроме обычной, свои тематические сеты (ивентовые вроде Scarecrow Jack, легендарные Crittermaster Alpha, Glorious Mech).
  - После 1000-го этапа открывается «трансморф» — облик вещи отдельно от статов.
  - То есть в TT2 вид меняется **целыми тематическими наборами** (шлем + нагрудник), а аура и слэш дают «вау» эффектом, а не силуэтом. Подробной вики с картинками получить не удалось (страница fandom закрыта).
- **Terraria** ([вики](https://terraria.wiki.gg/wiki/Armor)) — самый близкий пример маленького пиксельного героя:
  - 70 комплектов брони (голова, торс, ноги) с бонусом за полный набор;
  - у части комплектов варианты под разные классы;
  - отдельные «косметические» слоты (vanity) меняют вид без статов, некоторые костюмы прячут броню под собой;
  - у многих комплектов отдельные женские спрайты;
  - спрайты брони со временем перерисовывают.
- **MapleStory**: вещи — слои, которые собираются в один спрайт; огромные эффекты экипировки можно отключить ([форум Nexon](https://forums.maplestory.nexon.net/discussion/comment/42877), [maplestory.io](https://deepwiki.com/crrio/maplestory.io/3.2-avatar-factory)).
- **Soulbound** ([разбор разработчиков](https://soulbound.game/news/how-we-built-a-pixel-art-character-and-cosmetic-system/)):
  - снаряжение — слои голова, торс, ноги, спина, оружие на общем скелете с общим числом кадров;
  - порядок слоёв меняется от направления и оружия;
  - под разные типы оружия свой вариант нагрудника;
  - трансмог отделяет вид от статов;
  - все вещи в одной палитре.
- **Вывод для нас:**
  - наш риг уже устроен так же (слои на общем скелете, вещь — скин), значит, массивную броню и аксессуары можно наращивать без переделки;
  - стоит взять у TT2 тематические полные наборы и эффект-ауру по редкости, у Terraria — отдельный косметический облик поверх статов.

Доска референсов брони (32 стиля: 18 исторических, 14 фэнтезийных) собрана из открытых изображений через Openverse. Картинки лежат только в рабочей папке сессии и в репозиторий не кладутся: лицензии разные, часть некоммерческие. Авторы и ссылки — в файле к доске.

### 13.4. Силуэты как в Terraria, детали как в TT2 (решение Сергея 10.11.2026)

  - у комплекта одна тема, и узнаётся она по шлему, который часто выходит за голову;

## 14. Герой в 2× детальности (10.11.2026)

Сергей: «Хочу такую же броню, как в наборах itch.io и CraftPix, чтоб прям видна была». На вопрос, как этого добиться, выбрал **«Увеличить героя»**. Образцы — все четыре набора с доски: misnina 32px Armor Sets, EmblemAdept Fantasy / Greece & Rome, cyangmou / Idylwild, CraftPix (100 Armor Icons, Knight).

**Почему броня в наборах видна, а наша — нет:**
- в наборах каждая вещь — иконка 24–32 px, у нас весь герой около 54 px (шлем около 16 px, нагрудник 11 × 14), то есть на вещь в 4–6 раз меньше пикселей;
- там у каждой вещи своя тёмная обводка, 5–6 тонов и блик на металле;
- у нас обводка шла только по силуэту героя, а края внутри были в тон материала.

**Как сделано:**
- **Нативное разрешение героя ×2.** Рост около 108 px. В полоске герой выводится 1:1, без увеличения ×2: пиксель героя теперь мельче пикселя врагов (Сергея предупредили при выборе).
- **Скелет не менялся.** 1 единица мира = 1 пиксель куклы v8. Кости, IK, физика и все анимации v8 остались как были. У вложений вдвое больше пикселей на ту же площадь (`doll_base.K = 2`). Рантайм рисует в текстуру вдвое выше: в превью окно 192 × 128 / 192 × 160 на тот же вид мира.
- **Части v8 переведены в 2× алгоритмом Scale2x.** Это тот же алгоритм, что v8 использует для поворота: края остаются пиксельными. Точки крепления пересчитаны (`native_pivot`). Тело, лицо и кисти позже стоит дорисовать в 2× руками.
- **Текстуры:** нативные части увеличены ещё в 4 раза (`parts_tex`) для качественного поворота. Нативные картинки лежат в `parts_native`.
- **Броня в нативном 2×:** `tools/pix.py` — генератор пиксель-арта: фигура заливается материалом, свет справа сверху даёт три тона и полосу блика, у каждой вещи своя тёмная обводка, детали ставятся по пикселям. `tools/armor2x.py` — сами вещи. Каждая вещь привязана к своей части тела сдвигом, точка крепления считается от точки части (`BODY_PIVOT`), поэтому вещь садится ровно туда, где деталь v8.
- **Первый комплект — латы стража (`plate_late`) в 2×:**
  - закрытый шлем с золотым гребнем, смотровой щелью, дыхательными отверстиями, ободом и заклёпками;
  - кираса с ребром и поясом с камнем;
  - три полосы юбки и набедренники с кантом;
  - табард с крестом;
  - трёхъярусные наплечники с кантом, заклёпками и камнем;
  - наручи, налокотник, рукавицы с пластинами пальцев, раструб;
  - поножи с наколенником, сабатоны с полосами;
  - пластины поясницы.

  Остальные пять баз и аксессуары **пока** увеличены из 1× (Scale2x) — их перерисую в 2× по тому же генератору.

**Проверка:**
- диагностика рига и автопоиск разрывов в броне: разрывов нет;
- превью: `base/hero/preview/knight_2x.png` (рыцарь без брони и в латах стража по редкостям, со щитом);
- сверка с v8 теперь сравнивает с увеличенными кадрами v8: расхождение 8–14% — это сглаженные края Scale2x и тонкая обводка, а не ошибки рига.

**Что меняется в игре:**
- текстура героя в полоске вдвое выше разрешением (около 192 × 128 px на кадр 96 × 64 мира);
- герой рисуется 1:1, а не ×2;
- обводка по слоям — 1 нативный пиксель.

**Дальше:**
1. перерисовать в 2× остальные базы и аксессуары;
2. дорисовать в 2× лицо, кисти и тело;
3. стили (японский, готический, кость, кристалл, божественный).

## 15. Первый персонаж класса: Runedancer (10.11.2026, на утверждение)

Сергей: «Посмотри на персонажей и создай 2D-модель персонажа». Ответы на вопросы: первой делаем **Runedancer**, на **текущем Spine-риге 2×**, в объёме **облик + оружие + свои анимации + эффекты удара**.

**Как персонаж класса ложится на общий риг.** Персонаж — это набор скинов и своя папка анимаций на том же скелете. Броня сетов надевается поверх, как на базовых героев.

| Что | Где | Имя в Spine |
| --- | --- | --- |
| Облик и оружие | `tools/runedancer2x.py` | скины `hair/runedancer`, `eyes/runedancer`, `outfit/runedancer`, `weapon/rune_daggers` |
| Анимации | `tools/runedancer_anim.py` | `runedancer/Idle`, `Enter`, `Hit1`–`Hit3`, `Exit1`–`Exit3` |
| Эффекты | `tools/class_fx.py`, `fx/runedancer/`, `fx/src/rune-word.js` | события `hit` и `fx` в анимациях, строка события — имя эффекта |
| Набор скинов | `hero.meta.json` → `presets.runedancer` | — |

Новый класс добавляется так же: модуль облика в `doll_base.CLASSES`, модуль анимаций в `doll_skeleton.CLASS_ANIMS`, запись в `class_fx.CLASSES`.

**Облик** (лор — `lore.md` §5.1: танцовщица, которая пишет руны кинжалами). Всё нарисовано в нативном 2× генератором `pix.py`:
- **Силуэт-примета:** высокий хвост с золотыми кольцами (дуга за головой, кость `hair_fly` с физикой), пучок с золотой заколкой, налобная цепочка с красным камнем.
- **Наряд:** короткий багровый топ с золотым кантом и монетками, открытый живот, пояс-кушак с узлом и хвостом (`coat_tail`, физика), шаровары цвета слоновой кости с золотыми манжетами, туфли с загнутым носком, золотые браслеты (`bracer`) и обмотки на предплечьях, вуаль за спиной (`cape`, физика).
- **Палитра:** багровый + золото + слоновая кость, волосы тёмно-фиолетовые, глаза янтарные. Холодное свечение есть только на рунах клинков, поэтому оружие читается первым.
- Причёска построена от сетки женской головы v8 (Scale2x по буквам), поэтому лицо и чёлка совпадают с базой, а шлемы сетов садятся без правок.

**Оружие — парные рунные кинжалы.**
- Новая кость `weapon_far` на дальней кисти и слот `weapon_far` в заднем слое (перед дальней рукой). Раньше во второй руке был только `offhand`, он держит горизонт (щит), а кинжалу нужно вращение за кистью.
- В позах добавлен ключ `swB` — угол дальнего клинка, по смыслу как `sw`.
- Скин `weapon/rune_daggers` кладёт один клинок в оба слота; дальний темнее цветом слота, как вся дальняя сторона.
- У старых анимаций ключей `weapon_far` нет, они не изменились.

**Анимации** (позы на языке куклы v8, длительности в мс; Spine интерполирует на 60 к/с):
- `Idle` — стойка танцовщицы: ближний клинок вперёд-вверх, дальний обратным хватом, дыхание 12 ключей по 80 мс.
- `Hit1` — замах со спины, выпад и горизонтальный рез ближним клинком.
- `Hit2` — восходящий рез дальним клинком, корпус раскрывается к зрителю.
- `Hit3` — присед, пируэт в прыжке (виды торса спина → профиль → фас, руки с клинками меняются сторонами) и двойной укол в выпаде.
- Связка идёт по кругу 1 → 2 → 3 → 1; `Enter` и `Exit1–3` — вход и возврат в стойку.

**Эффекты** (плагин pixelfx, MIT, `art/LICENSES.md`):
- `rune_slash` (удар 1) и `rune_rise` (удар 2, тот же слэш, отражённый по вертикали) — серп `melee/sword-slash`;
- `rune_spin` (пируэт) — кольцо `melee/spin-slash`;
- `rune_word` (конец удара 3) — **свой эффект** `fx/src/rune-word.js`: пять малых рун встают по кругу, в центре белой вспышкой ставится большая руна, печать остывает и осыпается. Это «Слово» Пути «Танец рун».
- Каждый эффект отрендерен в пяти цветах рун: Пламя, Иней, Гром, Тень, Свет (`fx/runedancer/<эффект>_<руна>.png`). Какой цвет играть, решает игра по текущей руне.
- `fx/runedancer/fx.json`: кадры, fps, точка привязки листа (`pivot`) и место относительно корня героя в единицах мира (`anchor`). 1 пиксель эффекта = 1 единица мира = 2 нативных пикселя героя, то есть пиксель эффекта совпадает с пикселем врагов.
- В анимациях стоят события Spine: `hit` в момент удара (строка — имя эффекта) и `fx` для эффекта без урона.

**Проверка** (`python3 class_preview.py runedancer`, превью в `base/hero/preview/`):
- `class_runedancer.png` — облик; `class_runedancer_poses.png` — 9 крайних поз, автопоиск разрывов: разрывов нет (`class_runedancer_defects.json`);
- `class_runedancer_play.gif` — стойка и две связки с эффектами; `class_runedancer_frames.png` — кадры связки;
- сверка базовых героев с v8 не изменилась (`silhouette_diff_percent.json`), диагностика рига — без дефектов.

**Чего нет и что дальше:**
- Хвост и вуаль в связке качаются слабо: физику (`hair_fly_physics`, `cape_physics`) стоит подстроить в редакторе Spine.
- Слэши взяты из библиотеки pixelfx как есть (серп сверху вниз), а `Hit1` — горизонтальный рез: свой плоский слэш под кинжал — следующий шаг.
- Эффекты — отдельные листы, в игре их проигрывает движок по событию; в Unity не проверено (UnityMCP в облаке недоступен).
