# Техспецификация графического конвейера в Blender (для ИИ-агента)

Агент управляет Blender через Python API (`bpy`), например через MCP-сервер для Blender или запуском `blender --background --python`. Результат конвейера — **спрайт-листы и иконки для Unity** в мультяшном стиле, как в Tap Titans 2 (сеттинг: Страж Разлома против Колоссов, см. setting-options.md). Технические требования движка — в engine-spec.md.

---

## 0. Жёсткие правила
1. **Свои дизайны.** Вдохновляемся тоном TT2, но не копируем персонажей, врагов, логотипы и арт Game Hive и других игр.
2. **Лицензии исходников.** Сторонние модели, текстуры и HDRI берутся только с лицензией, разрешающей коммерческое использование (CC0, CC-BY с атрибуцией или купленные). Источник и лицензия каждого файла записываются в `art/LICENSES.md`.
3. **ИИ-контент учитывается.** Если модель, текстура или концепт сделаны генеративным ИИ, это отмечается в `art/AI_CONTENT.md` (нужно для раскрытия в Steam).
4. **Всё воспроизводимо скриптами.** Агент не делает «руками» то, что нельзя перезапустить. Рендер любой сущности = один запуск скрипта с параметрами.
5. **Исходники не перезаписываются.** `.blend` хранятся с версиями (Git LFS), результаты рендера лежат отдельно и генерируются заново.

---

## 1. Версии и окружение
- Blender: актуальная LTS-версия (зафиксировать номер в `art/BLENDER_VERSION`), движок рендера **EEVEE**.
- Python-скрипты в `art/scripts/`, запускаются и из интерфейса, и headless: `blender -b file.blend -P render_entity.py -- --entity goblin_giant --anims all`.
- Дополнительно: Pillow для упаковки листов и даунскейла (или встроенные средства Blender, если Pillow недоступен).

## 2. Структура папок
```
art/
  BLENDER_VERSION
  LICENSES.md, AI_CONTENT.md
  templates/
    render_template.blend     камера, свет, toon-материал, контур, настройки рендера
  palettes/
    biomes.json               палитры биомов (HEX)
  entities/
    hero_blade/               hero_blade.blend, entity.json
    goblin_giant/             goblin_giant.blend, entity.json
    ...
  icons/
    gems/, items/, currencies/
  vfx/                        текстуры эффектов (вспышки, искры, руны)
  scripts/
    render_entity.py          рендер анимаций сущности в кадры
    pack_sheet.py             упаковка кадров в спрайт-лист + метаданные
    make_variants.py          перекраски и сборка из частей
    render_icons.py           иконки гемов/предметов
    validate.py               проверки качества (раздел 8)
  out/                        результат (не редактируется руками)
    sprites/<entity>/<anim>.png + <entity>.json
    icons/...
```
Unity берёт файлы из `art/out/` (копирование в `Assets/Game/Art/` отдельным скриптом).

## 3. Шаблон сцены (`render_template.blend`)
- **Камера:** ортографическая, вид сбоку с лёгким поворотом (3/4, около 20–25° по Z), чтобы фигура была объёмнее. Высота кадра фиксирована по сетке «1 юнит = N px».
- **Ориентация:** герой смотрит **вправо**, враги **влево** (герой слева, враг справа, §2.7 концепта).
- **Свет:** ключевой свет сверху-спереди, контровой свет (rim) сзади-сбоку для читаемого силуэта, мягкий заполняющий. Без теней на полу: фон прозрачный.
- **Toon-материал:** Diffuse → Shader to RGB → ColorRamp на 2–3 ступени (тень, свет, блик), плюс параметр «основной цвет» для перекрасок.
- **Контур:** inverted hull (Solidify с перевёрнутыми нормалями и тёмным материалом) или Line Art. Толщина контура задаётся в пикселях итогового спрайта (≈2 px), чтобы при уменьшении не пропадала.
- **Рендер:** Film → Transparent, цвет sRGB / Standard (не Filmic/AgX, чтобы цвета палитры совпадали), сглаживание включено.
- **Разрешение рендера:** в **4 раза больше** итогового спрайта, затем уменьшение с Lanczos. Так контуры и детали остаются чистыми.

## 4. Размеры и анимации
| Сущность | Итоговая высота | Ячейка листа | Точка опоры (pivot) |
|---|---|---|---|
| Герой | 96 px | 128×128 | низ-центр |
| Обычный враг | 96–112 px | 128×128 | низ-центр |
| Босс, страж биома | 128 px | 160×160 | низ-центр |
| Иконка гема/предмета | 64 px (рендер 256) | 64×64 | центр |

**Набор анимаций** (12 кадров/с в Unity):
| Анимация | Кадров | Кто | Примечание |
|---|---|---|---|
| idle | 8 | все | лёгкое дыхание, зациклено |
| attack | 4–6 | герой (по классам), боссы | быстрый взмах, удар на 2–3 кадре |
| hit | 3 | враги, боссы | отдача назад, белую вспышку делает движок |
| death | 6–8 | враги, боссы | падение или распад, растворение делает движок |
| cast | 6 | герой | для скиллов и песен Металлиста |

Появление врага («поп») и вспышки делает **движок**, их в Blender не рендерим.

## 5. Описание сущности (`entity.json`)
```json
{
  "id": "goblin_giant",
  "type": "enemy",
  "biome": "green_hills",
  "height_px": 104,
  "cell": [128, 128],
  "facing": "left",
  "anims": { "idle": 8, "hit": 3, "death": 7 },
  "palette_slots": ["skin", "cloth", "accent"],
  "variants": [
    { "id": "goblin_giant_red", "colors": { "skin": "#7DBE4E", "cloth": "#B23A3A" } },
    { "id": "goblin_giant_frost", "colors": { "skin": "#9FC9E8", "cloth": "#3A5BB2" }, "swap": { "weapon": "ice_club" } }
  ]
}
```
`type`: `hero`, `enemy`, `boss` или `warden`.

## 6. Скрипты
- **`render_entity.py --entity <id> [--anims idle,hit] [--variant <id>]`** — открывает `.blend` сущности поверх шаблона, применяет вариант (цвета, смену частей), рендерит каждый кадр каждого действия (Action) в `out/tmp/`.
- **`pack_sheet.py --entity <id>`** — уменьшает кадры до итогового размера, пакует в лист (по строке на анимацию, фиксированная ячейка) и пишет метаданные для Unity:
```json
{ "entity": "goblin_giant", "cell": [128,128], "pivot": [0.5, 0.0], "fps": 12,
  "anims": { "idle": {"row":0,"frames":8,"loop":true}, "hit": {"row":1,"frames":3,"loop":false},
             "death": {"row":2,"frames":7,"loop":false}, "hit_frame": {"attack": 2} } }
```
- **`make_variants.py`** — массово создаёт варианты: перекраска через параметры материала, смена частей через коллекции (оружие, шлем, рога). **Один базовый Колосс должен давать 3–4 вида врагов.**
- **`render_icons.py`** — иконки гемов (форма по типу: скилл, поддержка, триггер; цвет по атрибуту: красный, зелёный, синий, белый), предметов, валют. Единый ракурс и свет.
- **`validate.py`** — проверки из раздела 8, выходит с ошибкой, если хоть одна не прошла.

## 7. Палитры биомов (`palettes/biomes.json`)
- По 6–8 цветов на биом: Зелёные холмы, Песчаные руины, Ледяной пик, Вулканическая кузня, Небесные острова, Сердце Разлома.
- Враги биома используют его палитру для основных цветов, акценты (глаза, оружие, магия) контрастные.
- Цвета атрибутов фиксированы для всей игры: Сила — красный, Ловкость — зелёный, Интеллект — синий, любой — белый (совпадает с цветами гемов).

## 8. Проверки качества (`validate.py`)
1. **Тест силуэта:** спрайт заливается чёрным на 96 px и сравнивается с другими врагами биома. Силуэты должны различаться (например, по площади и контуру), иначе предупреждение.
2. **Размер:** фигура по высоте в пределах ±4 px от `height_px`, pivot на земле, ничего не обрезано краем ячейки.
3. **Альфа:** нет полупрозрачного «ореола» по краям (premultiplied alpha или dilation цвета под прозрачностью).
4. **Палитра:** основные цвета не выходят за палитру биома больше чем на заданный допуск.
5. **Контур** виден на итоговом размере (толщина ≥ 1.5 px).
6. **Вес файлов:** лист одной сущности ≤ 1 МБ PNG.
7. **Кадры удара:** в `attack` отмечен кадр попадания (`hit_frame`), чтобы движок синхронизировал урон и цифры.

## 9. Источник моделей (гибрид)
- **Человекоподобные герои:** базовая модель (купленная, CC0 или сгенерированная 3D-генератором) → автоматический риг через Mixamo → агент ретаргетит и правит анимации, ставит материалы, рендерит.
- **Колоссы и звери:** базовые меши плюс процедурные детали (рога, шипы, броня) скриптами, сборка из частей.
- **С нуля агент делает:** простые формы (слизни, големы из камней, кристаллы, сундуки), иконки, эффекты.
- **Сложное художественное (лица, выразительные позы)** проверяет и при необходимости правит человек.

## 10. Этапы для агента с критериями приёмки
**B1. Шаблон.** `render_template.blend`: камера, свет, toon-материал, контур, прозрачный фон. Тестовый куб и сфера рендерятся в 128×128 с чистыми краями.

**B2. Первый враг.** Гоблин-великан (Зелёные холмы): idle, hit, death. Спрайт-лист и JSON проходят `validate.py`. Скриншот в полоске Unity показывает, что враг читается на 96 px.

**B3. Герой.** Викинг (первый персонаж MVP, `skills.md`): idle, attack, cast. Удар читается за 4–6 кадров.

**B4. Варианты.** Из гоблина 3 варианта перекраской и сменой частей. Силуэты проходят тест.

**B5. Биом MVP целиком.** 6 врагов, 1 босс (Король-кабан), 1 страж (Древний Энт), второй персонаж MVP (Металлист, `skills.md`).

**B6. Иконки.** 5 Артефактов Разлома и предметы. Иконки скиллов, гемов, вкладок и валют — плоские силуэты game-icons.net, их собирает скрипт интерфейса (roadmap 12.11, решение Сергея 25.10.2026), Blender для них не нужен.

После каждого этапа: превью-лист в `art/out/preview/` для утверждения человеком, а дальше в работу только утверждённое.

## 11. Что агент спрашивает у человека
- Утверждение арт-направления после B1–B2 (стиль контура, ступени тени, палитра).
- Покупку или выбор источника базовых моделей и анимаций.
- Решения по лицам и ключевым персонажам (герой, боссы).
- Любые отступления от правил §0.
