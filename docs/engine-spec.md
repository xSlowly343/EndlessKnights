# Техспецификация движковой части (для ИИ-агента)

Документ для агента, который будет писать код. Дизайн игры — в concept.md, цифры контента — в content-draft.md. Здесь описано **как** устроен код: модули, интерфейсы, данные, правила и этапы с критериями приёмки.

---

## 0. Жёсткие правила (агент не нарушает никогда)
1. **Приватность ввода.** Коды клавиш не покидают поток ввода: их нельзя хранить, логировать, сериализовывать и отправлять в сеть. Наружу выходят только счётчики и категории (обычная клавиша, Enter, Backspace, пробел).
2. **Никаких глобальных хуков** `SetWindowsHookEx` (WH_KEYBOARD_LL / WH_MOUSE_LL), никаких инъекций DLL, чтения чужой памяти и оверлеев внутри чужих процессов. Ввод только через Raw Input (`RIDEV_INPUTSINK`).
3. **Игровая логика детерминирована** и работает тиком 10 Гц (`dt = 0.1`), независимо от FPS. Рендер только отображает состояние.
4. **Ядро (`Game.Core`) не зависит от UnityEngine.** Это чистый C#, тестируемый NUnit и пригодный для сервера.
5. **Баланс только в JSON** (`StreamingAssets/Data`), а не в коде. Ни одного «магического числа» урона, HP или цены в C#.
6. **В горячем цикле нет аллокаций:** `Instantiate/Destroy` и LINQ в Update и тике запрещены, только пулы.
7. Секреты (ключи Steam, адрес и ключ сервера, сертификаты) в репозиторий не коммитятся. Если они нужны, агент спрашивает человека.
8. **Удалять файлы и папки без спроса нельзя** (код, ассеты, документы, сейвы, `git rm`, перезапись файла целиком, удаление через MCP). Исключение — временные файлы своей текущей задачи.
9. **Никаких заметок в коде:** без комментариев, `TODO`, закомментированного кода и шапок. Заметки — в `docs/dev-notes.md`, `docs/todo.md` и описании PR.

## 3. Модуль ввода (`Platform/Input`)
**Интерфейс (в Core):**
```csharp
public interface IInputSource {
    InputSnapshot Drain();
}

public readonly struct InputSnapshot {
    public readonly int KeyDowns;
    public readonly int EnterDowns, BackspaceDowns, SpaceDowns;
    public readonly int LeftClicks, RightClicks, MiddleClicks;
    public readonly int WheelTicks;
    public readonly float MouseDistancePx;
    public readonly int Flicks;
    public readonly float CircleTurns;
    public readonly double SecondsSinceLastInput;
    public readonly float RhythmCv;
    public readonly bool Suppressed;
}
```
Пояснения к полям (в коде их нет, по правилу §0.9): `Drain()` забирает накопленное с прошлого вызова и вызывается из тика 10 Гц; `KeyDowns` без автоповтора и модификаторов; `WheelTicks` = |delta| / 120; `Flicks` — резкие взмахи; `CircleTurns` — полные обороты; `RhythmCv` — коэффициент вариации интервалов для анти-макроса; `Suppressed` — чёрный список, пауза или фуллскрин.
**Реализация `RawInputService`:**
- Свой поток, свой **message-only окно** (`HWND_MESSAGE`) и свой цикл `GetMessage`. В WndProc Unity **не** лезем.
- `RegisterRawInputDevices`: клавиатура (0x01/0x06) и мышь (0x01/0x02), `RIDEV_INPUTSINK`.
- Отброс событий с `hDevice == IntPtr.Zero` (инжектированный ввод).
- Клавиатура: считаем только make (без `RI_KEY_BREAK`), битовая маска 256 бит против автоповтора, модификаторы (Shift, Ctrl, Alt, Win) не считаем.
- Мышь: `MOUSE_MOVE_RELATIVE` — суммируем длину дельт; `MOUSE_MOVE_ABSOLUTE` — дельта от прошлой точки. Учесть скорость указателя (`SPI_GETMOUSESPEED`) и калибровку из настроек.
- Взмах: скорость выше порога в окне 80 мс. Круг: накопление угла по знаку векторного произведения соседних дельт.
- Анти-jiggler: движения короче порога за 250 мс не считаются.
- Счётчики через `Interlocked`, `Drain()` атомарно обнуляет.
- Подавление: `GetForegroundWindow` → имя процесса → чёрный список (проверка раз в 500 мс, а не на каждом событии).
- **Режим редактора:** `UnityInputSource` поверх Input System (Raw Input в редакторе капризный), а также `FakeInputSource` для тестов и ботов-симуляций.

**Мягкие капы применяются в Core, а не во вводе** (значения в `Data/input_caps.json`): клавиши — полный урон до 8/с, √ до 15/с, выше не считается; клики — до 10/с.

## 4. Окно (`Platform/Window`)
`WindowController` (вызывается один раз после старта, затем по событиям):
- Своё окно ищется через `EnumWindows` (PID и класс `UnityWndClass`) → стиль `WS_POPUP`, ex-стили `WS_EX_TOPMOST | WS_EX_APPWINDOW`. Игра видна в Alt+Tab и на панели задач (решение Сергея 19.10.2026).
- **Режимы фокуса:** по умолчанию клик по игре делает её активной. Кнопка-иконка на полоске включает режим «без фокуса»: добавляется `WS_EX_NOACTIVATE`, клики по игре не забирают фокус у рабочего приложения. Режим выключается, когда игру выбрали через Alt+Tab или панель задач (окно получило `WM_ACTIVATE`). Режим не запоминается: каждый запуск начинается в обычном режиме.
- Прозрачность: `DwmExtendFrameIntoClientArea(margins = -1)` и камера с clear color (0,0,0,0). В Player Settings отключить «Use DXGI Flip Model swapchain», если прозрачность не работает (проверить на прототипе).
- Клики насквозь: переключение `WS_EX_TRANSPARENT` каждый кадр по результату raycast под курсором (UI или спрайт есть → кликабельно).
- `TaskbarDock`: `SHAppBarMessage(ABM_GETTASKBARPOS)`, авто-скрытие панели, несколько мониторов (`MonitorFromWindow`), per-monitor DPI v2. Реакция на `WM_DISPLAYCHANGE` и `WM_DPICHANGED`.
- `FullscreenWatcher`: раз в 1 с `SHQueryUserNotificationState`, при фуллскрине скрыть окно и поставить рендер на паузу (логика продолжает тикать).
- **Режим панели:** по клику окно временно увеличивается и центрируется (дерево, Книга умений, артефакты, статистика, настройки), по закрытию возвращается в полоску. Второе окно не открываем.
- `TrayIcon`: меню «Пауза», «Клики насквозь», «Поверх всех окон», «Выход»; «Панель» добавится вместе с режимом панели. Полоска прячется только в эксклюзивном полноэкранном режиме и в режиме презентации (`FullscreenWatcher`); поверх игр в окне и в окне без рамки на весь экран она остаётся; если выключить «Поверх всех окон», её перекрывают обычные окна, в том числе развёрнутые (решение Сергея 20.10.2026).

## 5. Ядро симуляции (`Core/Sim`)
```
GameLoop (10 Гц)
  snapshot = input.Drain()
  InputRules.Apply(snapshot, caps)       → EffectiveInput
  FocusSystem.Tick                       → Фокус
  EnergySystem.Tick                      → Энергия, ноты Барда
  TriggerSystem.Tick                     → какие гемы-триггеры срабатывают
  SkillSystem.Tick                       → активные эффекты, откаты, ауры
  CombatSystem.Tick                      → урон по врагу, DoT, криты
  StageSystem.Tick                       → смерть врага, спавн, босс, таймер, провал
  LootSystem.OnKill                      → золото (в MVP); гемы и предметы с фазы 14а
  events → EventQueue (для Presentation и Net)
```
- **События:** `Damage(amount, isCrit, source)`, `EnemySpawned`, `EnemyKilled`, `BossStarted`, `BossFailed`, `LootDropped`, `SkillCast`, `AuraChanged`. Presentation подписывается и рисует.
- **Состояние** (`GameState`) сериализуемо целиком и не содержит ссылок на Unity.
- **Детерминизм:** свой `Rng` (xorshift128+) с сидом в сейве; никаких `UnityEngine.Random` и `System.Random` в Core.
- **Офлайн-прогресс:** `OfflineCalculator.Simulate(state, seconds)` аналитически (формула, а не прогон тиков), потолок из данных (8–12 ч). Стражей биома офлайн не проходит.

## 6. Статы и модификаторы (`Core/Stats`)
- `Modifier { Stat, Kind: Flat | Increased | More, Value, Tags, Condition? }`.
- Итог: `(база + ΣFlat) × (1 + ΣIncreased) × Π(1 + More)`, как в PoE.
- **Теги:** `Keyboard, Mouse, Click, Idle, Skill, Aura, DoT, Crit, Gold, Minion…`. Модификатор применяется, если теги совпали.
- Источники: узлы дерева, аффиксы предметов, гемы и поддержки (поддержка действует только на скилл, в чьём сокете стоит), ауры, Артефакты Разлома.
- `StatSheet` пересчитывается **только при изменении билда**, кэшируется. В тике только чтение.

## 7. Большие числа (`Core/Math`)
- `BigNumber { double Mantissa (1 ≤ m < 10); long Exponent; }` — сложение, умножение, деление, степень, сравнение, `Log10`.
- `NumberFormatter`: режимы Letters (K, M, B, T, aa, ab, … zz, aaa), Scientific, Engineering, Full (до 1e15). Знаков после запятой 0–3, разделитель по языку.
- 100% покрытие юнит-тестами.

## 9. Сейвы (`Core/Save`)
- JSON: `version`, `savedAt`, `state`, `checksum`. Миграции по версии.
- Автосейв каждые 30 с и при выходе; запись атомарно (`.tmp` → rename), 3 ротационных бэкапа.
- Путь: `%AppData%/<Studio>/<Game>/save.json`, синхронизация Steam Cloud. Позже — серверная копия.

### 9.1. Статистика ввода
- `InputStats` в `Game.Core`: `ulong Keys`, `ulong Clicks` (плюс по кнопкам), `double MouseMeters`. Два экземпляра: сессия (только в памяти) и всё время (в сейве).
- Пополняется из `InputSnapshot` **до** кап боя, но после отброса программного ввода и автоповтора.
- Пиксели в метры: `PhysicalMonitorInfo` в `Platform/Window` отдаёт мм на пиксель для каждого монитора (EDID, запасной вариант 96 DPI × масштаб). Путь считается по позиции курсора на том мониторе, где он сейчас.
- Формат: `StatFormat.Distance(meters)`: меньше 1000 → `"{0} м"` целым; иначе километры, обрезанные вниз до сотых, `"{0:0.00} км"` с разделителем тысяч. Покрыть тестами: 0, 999.999, 1000, 2054, 1 204 370 м.

## 10. Отображение (`Presentation`)
- `Application.targetFrameRate = настройка (60)`, `QualitySettings.vSyncCount = 0`. Режим батареи: `OnDemandRendering.renderFrameInterval = 2`.
- Интерполяция между тиками для плавности (рендер 60 FPS, логика 10 Гц).
- Пулы: цифры урона (30), частицы, снаряды, монеты.
- `DamageNumbers`: слияние событий в окне 0.3 с, лимит объектов на экране.
- Враги появляются «попом» 0.1–0.15 с (масштаб), без анимации движения. Смерть — 0.2 с растворение и частицы.
- Анимации: спрайт-листы из Blender (toon-рендер), импорт через Sprite Atlas.

## 11. Сеть (`Net` и `Server/`)
- Вход: Steam session ticket → `AuthenticateSteamAsync` в Nakama.
- **Синхронизация асинхронная:** раз в 15 с отправка агрегатов (урон по рейд-боссу, этап, счётчики ввода за период). Никогда — коды клавиш.
- **Отряд (пати до 4):** хозяин боя — Nakama authoritative match (TypeScript), в прототипе — владелец Steam-лобби на App ID 480. Общая полоска HP в долях, клиент присылает урон пакетами раз в 0,5 с, сервер рассылает состояние боя 2 раза в секунду. Логика хозяина боя — `Core/Party` (`PartyEncounter`, `PartyClient`), подробно в coop.md.
- **Серверная проверка** (TypeScript-модули Nakama): капы урона в секунду от `StatSheet` снимка, капы ввода, отбраковка аномалий.
- Офлайн-режим: игра полностью работает без сети, а кооп-механики показывают «нет связи».

## 13. Этапы для агента с критериями приёмки
**M1. Окно.** Полоска у панели задач, прозрачный фон, поверх всех, есть на панели задач и в Alt+Tab, режим «без фокуса» по кнопке (печать в Блокноте не прерывается при клике по игре), клики насквозь на пустых местах, прячется в фуллскрине, иконка в трее.

**M2. Ввод.** `RawInputService` работает при игре не в фокусе. Отладочный оверлей показывает счётчики. Автоповтор не считается. Ввод AutoHotkey (`SendInput`) не считается. Модификаторы не считаются. Подписанная сборка проверена на VirusTotal, результат приложен.

**M3. Ядро боя.** `Game.Core` с тиком 10 Гц, StatSheet, BigNumber, этапы, босс с таймером, Фокус, Энергия. Юнит-тесты зелёные. Headless-симуляция «8 нажатий/с в течение часа» выдаёт ожидаемый этап.

**M4. Отображение.** Герой слева, враг справа, «поп» врага, взмах на удар, цифры урона со слиянием, полоска HP, таймер, 60 FPS в рамках бюджета CPU.

**M5. Классы и гемы MVP.** Печатник и Бард, 3 скилла и 1 триггер из `gems.json` (формат уже под все виды гемов). Книга умений на 3 слота со слотом триггера, без поддержек. Дерево на 72 узла из `tree.json` со всеми типами узлов, сброс за золото. Остальные механики идут по одной в фазе 14а roadmap, после каждой агент ждёт Сергея.

**M6. Сейв и офлайн.** Автосейв, атомарная запись, миграции, офлайн-расчёт с потолком.

**M7. Сеть и пати.** Вход через Steam в Nakama, список друзей, пати до 4, общий босс, серверные капы.

**M8. Прогрессия MVP.** Уровень героя и очки дерева, улучшения удара за золото, престиж (Эхо = корень от золота за забег) и 5 случайных Артефактов Разлома без повторов, soft wall. Headless-симулятор (roadmap 5.10) пишет CSV, по которому агент подбирает цифры (content-draft §6).

Этап M1–M8 — это группа задач roadmap. PR делается **на каждую задачу** (CLAUDE.md), а этап закрывается, когда все его задачи приняты; в последнем PR этапа — описание «до/после» и замер CPU, где применимо.

## 14. Что агент спрашивает у человека
- Сертификат подписи кода, Steam App ID, ключи Steamworks.
- Адрес и ключи сервера Nakama, доступ к VPS.
- Финальные арт-ассеты (до них агент использует заглушки).
- Любое изменение пунктов из §0.
